*[English](README.md)*

> *여울 — 개울이 돌 위로 얕고 빠르게 흐르는 구간 — 은 흩어진 생각이 부딪고 빨라져 정직하게 시험받는 곳이다.
> (영어권에는 이 지형을 뜻하는 "riffle"로 옮긴다.)*

**Yeoul은 심의 → 사전등록 → 자율 작업 루프를 자기기만과 성급한 종결에 저항하는 무결성 게이트와 함께
돌리는 파일 기반 하네스입니다.** 측정 규율 프리미티브(사전등록 + 변조 감지 원장) 위에 얹힌 *실천 계층*이에요 —
프리미티브는 기록된 증거의 무결성을 확인하고, Yeoul은 *"규율 있는 아이디어 루프를 처음부터 끝까지 어떻게 돌리나?"*에 답합니다.

> **v0.4.0: 독립 제품의 간편 설정·실행·복구.** 거울과 레인스택 없이 사용할 수 있습니다.
> [간편 사용 안내](docs/WORKSPACE_GUIDE.ko.md), [변경 기록](CHANGELOG.md),
> [검증 범위·기존 아크 안내](docs/INTEGRITY.md)를 확인하세요.

## 설치

```bash
pip install 'git+https://github.com/mirror-stack/yeoul@v0.4.0#subdirectory=mcp'
yeoul setup ./my-discussions --mode discuss
yeoul new example --workspace ./my-discussions
yeoul doctor --workspace ./my-discussions
yeoul connect --workspace ./my-discussions
```

`yeoul connect`가 출력한 서버 항목을 사용 중인 MCP 클라이언트에 추가하세요.
기존 설정은 자동 수정하지 않습니다. Python 3.10+와 Bash(Windows: Git Bash)가 필요합니다.
소스 설치의 `setup/install.sh`도 여울만 설치하며,
`--with-mirror-stack`을 선택해야 거울을 함께 설치합니다.
원장은 별도 폴더에 두고 파일별 읽기 권한으로 연결할 수 있습니다.
관리 모드 종결은 외부 기록기를 실행하지 않습니다. 기존 원시 CLI·스크립트는
고급 로컬 인터페이스이며 제품 CLI/MCP의 공통 잠금 밖에 있습니다.

## 빠른 시작

에이전트도 연산도 없이 — 구조와 게이트만 돌려봅니다:

```bash
examples/demo.sh       # 전 라이프사이클: 스캐폴드 → 아크 → 2단계 KILL 종결 → 개발 핸드오프 → 검증 게이트
tests/test_gates.sh    # 모든 게이트의 단언 기반 스모크 테스트
```

방법론이 처음이면 [`docs/METHODOLOGY.md`](docs/METHODOLOGY.md)를 읽고,
[`docs/BOOTSTRAP_PROMPT.md`](docs/BOOTSTRAP_PROMPT.md)를 에이전트에 붙여 실천을 구성하세요.

## 무엇인가 (그리고 아닌가)

- **맞다**: 다역할 심의 아크를 열고, 폭주 가드 아래 수렴을 판정하고, 정직하게 종결하고(빈칸 거부 + KILL 방어
  체크리스트), 기계 검증되는 개발 루프로 넘기는 — 작은 셸 스크립트 + 템플릿 + 방법론의 묶음.
- **아니다**: 새로운 멀티에이전트 프레임워크. 오케스트레이션은 일부러 평범하게 두었습니다 — 가치는 *게이트*에 있지
  토론에 있지 않아요. 연구에 따르면 토론 라운드를 늘려도 답 품질은 **오르지 않습니다**; Yeoul의 라운드/토큰/무진전
  가드는 토론이 스스로 교정해서가 아니라 *표류하기* 때문에 존재합니다.

## 게이트 (진짜 가치)

- **Gate-1 (선행연구)** — 기존 연구가 이미 다룬 아이디어는 초기에 기각하거나 각도를 튼다.
- **kill 조건 우선** — 반증조건 없는 명세는 검증 불가. 연산을 쓰기 *전에* 봉인한다.
- **2단계 종결** — 종결은 요약 초안을 만들고, 빈칸이 채워져야만 봉인된다.
- **KILL 방어 5항 체크** — "실패" 판정은 앵커 재현·독립각도 ≥2·구현결함 배제·도감 대조·kill 문언 일치가 전부
  기록되기 전엔 봉인되지 않는다.
- **봉인 조건 대조** — 사전등록된 kill 조건이 아크에 연결돼 있으면, 종결이 **어떤 라벨이든** 그 조건에 답해야
  한다. 안 그러면 `converged`로 닫는 것만으로 *닫는 사람이 쓰지 않은 유일한 신호*가 꺼진다. 더 이상 읽히지 않는
  봉인은 건너뛰지 않고 거부한다.
- **검증 게이트 개발 루프** — 각 자동 개발 라운드는 TODO 한 항목을 진행하고, 그 항목의 기계 검증 명령이 exit 0일
  때만 체크할 수 있다. 판정은 에이전트 보고가 아니라 **하네스 재실행**이다. 검증 명령 없는 항목은 거부되며
  **체크된 항목도 마찬가지** — 절을 지우고 체크하는 우회가 막힌다. (실패할 수 없는 검증 명령은 여전히 구멍이고,
  그건 작성자 몫이다.)

## 계층

| 계층 | 무엇 | 위치 |
|---|---|---|
| 프리미티브 | 사전등록 + 변조 감지 원장 | *(선택 의존성 — mirror-stack)* |
| 실천 | 심의 아크·게이트·개발 핸드오프 | **이 레포** |

토론에는 mirror-stack이 필수가 아닙니다. 다만 봉인을 연결하면 원장 전체 해시·체인과 최초 봉인을 검증합니다.
토론 종결은 측정 결과나 출판 승인이 아닙니다. 측정 결과는 감독자가 `arc-result`에 상태와 증거를 명시해 넘깁니다.

개발 검증은 작업 전에 `verify-baseline`으로 기준을 고정한 뒤 `verify-gate`로 확인합니다.
Ralph는 최초 TODO를 부모 프로세스 메모리에 보관해 명령 변경·항목 삭제를 거부합니다.
기존 2줄 `.prereg`는 자동 인증하지 않으며, 같은 원장과 주장으로 명시적인 재연결이 필요합니다.

## 상태 / 정직 노트

- 자율 개발 루프("Ralph" 방식)는 **가장 덜 검증됐고 가장 commodity한** 부분입니다. 그 안전성은 루프 자체가 아니라
  기계 검증 게이트에서 나와요. 검증된 기법으로 과신하지 마세요.
- Yeoul이 연구 *결과*를 개선한다는 주장은 하지 않습니다. 지원하는 실행 경로에서 규율을 명시하고
  기계적으로 검사한다는 뜻이며, 운영체제 수준의 보안 경계나 진실성 증명은 아닙니다.
